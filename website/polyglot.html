Polyglot support

One program. Seven languages. The boundary you choose.

OrchestrateLang does not replace Rust, C, Python, or TypeScript. It coordinates them. A foreign function stays a direct call. Stateful or runtime-owned code becomes a service behind the same typed interface as any other serverlet. Each boundary is declared in the source, checked by the compiler, and costs what the table at the bottom says it costs.

Scores are 0 to 5 per column, 40 total. They describe fit with the current sidecar mechanism, not language quality. A language near the top of the table needs only four edits in the compiler: a ForeignSource variant, a toolchain entry, a build.rs emitter line, and a check-foreign entry.

The tier is a judgement about effort and route; the total is a measure of C-ABI fit. A language can rank low on the total yet be cheap to add through the TypeScript bridge, which is why JavaScript sits in "Ready to add". "Needs a different path" usually means a landline serverlet; "Would want a new feature" names the feature.

Scores were set against the int, float, bool, void sidecar. Version 0.8.0 added string and handle across the C ABI; arrays and structs would lift the whole table at once. The data lives in website/assets/scorecard-data.js; re-score there.

WebAssembly is not in this table, and not because it scored badly. The table asks how well a language fits the C-ABI sidecar slot; a .wasm module fits a different slot entirely — it is already compiled, so there is no toolchain to install, no static archive to build, and no cross-compilation question. It ships in 0.9.0 as load_foreign "wasm", and it is also the route by which a language with no C ABI can arrive: anything that targets WebAssembly can be called, at about 0.1 µs, without the compiler learning that language at all.

Two mechanisms, not seven

Foreign functions for calls. Serverlets for state.

Every language plugs in through one of two shapes, so there is one set of rules to learn. load_foreign puts functions in a module's namespace and keeps them stateless. A serverlet via python(...) or via typescript(...), called a landline, keeps a foreign process alive with its own state and answers typed calls. Serverlets can call foreign functions; foreign functions never own state. A compiled .wasm module plugs into the same load_foreign shape, and a sandboxed serverlet into the same serverlet shape.

load_foreign: a function you call directly
// math/module.orch
load_foreign "zig" "./vectors.zig"

// math/vectors.orch_ffi — the contract the compiler type-checks
length2d(x: float, y: float) -> float
gcd(a: int, b: int) -> int

// main.orch
use module math: "./math"
let d = math.length2d(3.0, 4.0)   // in-process, direct call
landline: a service that keeps state
// main.orch
serverlet Counter via python(source: "./counter.py", budget: "2ms") {
    on add(amount: int) -> int
}

orchestrator main() {
    let counter = start Counter()     // one persistent Python process
    print(to_string(counter.add(3)))  // state lives in Python
    print(to_string(counter.add(4)))  // 7
    stop_orch()
}
Choosing a boundary

Three questions pick the mechanism.

The design philosophy calls this the ladder: pick the lowest rung that meets the need. Asked as questions, it is short.

1. Do you need a function, or a thing with state?
A functionand the language exports C-callable symbols (Rust, C, C++, Zig, Swift): load_foreign. In-process, nanoseconds, no copies. Stateful native objects still fit here as an opaque handle.
State, or a long-lived servicego to question 2.
↓
2. Can the implementation be OrchestrateLang or Rust?
Yesan in-process serverlet: a Tokio task and a channel, the cheapest stateful boundary. Add secret when it should build as its own native executable and crash separately.
No, it is Python or TypeScriptgo to question 3.
↓
3. Do you trust the code?
Yesa landline: via python(...) or via typescript(...). A persistent process, a checked interface at startup, budgets for slow calls, and host callbacks you grant one function at a time.
Nosandbox(memory_limit: "64mb", timeout: "5s"). The handlers run in a WASM guest under wasmtime: memory capped, a call interrupted at its timeout, and no import it was not given. A child process is still not a security boundary — this is. grant on one is a compile error, because a grant would be a deliberate hole.

What crosses each boundary

Type rules, by mechanism.

The string ruleA parameter arrives NUL-terminated and is valid for the call only. A return must be allocated with the C allocator: the generated wrapper copies it into a String and frees it. Non-UTF-8 bytes are replaced; a NUL inside an OrchestrateLang string is dropped before the call.
The handle ruleA sidecar that returns handle names its release function once: drop release_counter(c: handle). The value calls it when its last owner drops, so a native object lives exactly as long as the OrchestrateLang value holding it. Handles pass by reference and are not wire types.

Foreign Rust

The .rs file is injected into the generated module and its sidecar registers the signatures. Types: int as i64, float as f64, bool, string as String, and type parameters such as reverse<T>(items: T[]) -> T[], which is how the generic standard library is written. A sidecar may declare Cargo dependencies under [dependencies]. Functions must be synchronous.

Because a string is a pointer and a length, a module that carries one must export the allocator both sides use — orch_alloc(i32) -> i32 and orch_free(i32, i32) — and the compiler says so if it does not. For load_foreign "wasm" the contract is checked against the module's own export table at build time, so a name it does not export, or a signature that does not line up, is an error naming both sides rather than a trap later. A sandboxed serverlet's guest is generated, so its allocator is generated with it.

What a landline guarantees

A checked interface, bounded waits, explicit callbacks.

Startup handshakeThe child process reports its protocol version and the ordered handler signatures it implements. A mismatch with the declaration closes the client and logs a diagnostic instead of failing on the first call.
Budgets and late repliesbudget: "2ms" bounds every call. With late: "drop" (the default) a late call returns the type's default; with late: "latest" it returns the most recent completed result, which a late reply then replaces. Use the p99 from the benchmark, not the median, to set it.
CrashesAn exception in a handler logs and returns a default while the process keeps its state. A process death during a call runs on_crash, returns a default without replaying, and restarts with fresh state. There are no configurable restart policies for landlines yet.
Host grantsIn library mode a landline may call Rust host functions, but only the ones it is granted: grant call world.record. Ungranted calls are rejected before dispatch. A grant constrains the generated interface; it does not restrict the process's filesystem or network.
PackagingPython builds copy the source and the bundled SDK into landline_<Name>/ beside the binary; Python itself stays external. A TypeScript landline compiles to an executable that needs neither Bun nor the source at runtime.
Not a sandboxA landline process has the same operating-system permissions as the orchestrator. Crash separation, yes; containment, no.

Each language keeps its own compiler, and its own diagnostics.

Not yet

Where the boundaries go next.

Direction, not compiler support. The roadmap carries the trade-offs.

TypeScript in-process Plannedscriptc 0.1.1 can emit a C-ABI static archive from a TypeScript module. A probe linked one into a C program: state persisted and a call cost 5.1 ns. Constraints found: no bigint in the static tier, strings as pointer plus length, arrays and structs deferred by scriptc. Would ship as load_foreign "typescript" "math.ts" (backend: "native").
Arrays and structs across the C ABI PlannedStrings and handles landed in 0.8.0; arrays and structs are the remaining gap between the fastest boundary and the landline boundary.
C# PlannedNative AOT exports with [UnmanagedCallersOnly] for functions; a landline or embedded runtime for services.
Go Exploring-buildmode=c-archive works, but only one Go library can be loaded per process, which is a real constraint on the module model.
Cross-compiling Zig and Swift PlannedBoth build for the host only today; build --lib --target with another target stops with a clear error.
Grants into a sandbox PlannedSandboxed serverlets ship in 0.9.0 under wasmtime, but a grant on one is a compile error rather than a hole that opens quietly. Each grant has to become one narrow, mediated host function in the wasmtime linker — the point where sandboxing and the consent model become the same mechanism. Arrays and structs across the guest boundary are planned with it.
