A compiled orchestration language

Say what runs, when it runs, and how the pieces talk.

OrchestrateLang is for the part of a program that coordinates everything else. Workers, event handlers, supervised processes, and stateful services are language constructs, not patterns assembled from async libraries. The compiler turns an .orch program into Rust, wires its concurrency through Tokio, and asks Cargo for a native binary.

The shape of the program is syntax

Four constructs, four responsibilities.

Coordination code usually hides its architecture inside library calls: spawn here, clone a sender there, wrap state in a lock, and remember who shuts everything down. OrchestrateLang makes the shape readable from the source.

orchestrator
owns

Startup, shutdown, lifecycle hooks, and the active process set. Also the entry point of a standalone binary.

automatic
owns

Recurring work on its own Tokio task, with a restart policy of never, a count, or always with backoff, and an on_crash handler.

on / trigger
owns

Typed event producers and any number of consumers. Handlers register on boot; a trigger broadcasts a payload to every listener.

serverlet
owns

Long-lived private state behind a typed client. Calls are handled one at a time, so nobody manages locks.

How a program runs

Compile to Rust. Do not hide a runtime.

There is no OrchestrateLang VM. orchestrate run main.orch walks the stages below and hands the result to Cargo. Set ORCH_SHOW_GENERATED=1 to read the Rust it wrote.

01Lex and parse.orch source into an AST
→
02Resolve modulesdirectory modules, PROM names, files merged by load
→
03Register and checktypes, signatures, generics, result and option
→
04Generate Rustprogram, modules, events, service clients
→
05Prepare foreign codeFFI adapters, child processes, landline assets
→
06Cargo builda Cargo project in .orch_cache/, then a native executable or an embeddable crate
Concurrency becomes Tokio tasks and channels. Native foreign functions link into the executable. Secret and landline services talk over a checked wire protocol.
Polyglot by choosing the right boundary

Use the cheapest boundary that works.

Not every dependency needs an actor or a child process. Reaching into other code has a ladder of costs; pick the lowest rung that meets the need. The figures are medians from the repository's own benchmark on one Apple Silicon Mac.

≈ 8 µs round trip
One service model, several boundaries

Every serverlet looks the same to its caller.

Start a typed service, keep its state alive, send it serialized calls. The variant decides where the implementation runs and what that boundary guarantees.

serverlet X { ... }Shipped

Trusted state with the lowest overhead: a Tokio task and a channel inside the program.

serverlet X secret { ... }Shipped

Compiled as a separate native executable. Process lifecycle, crash separation, and an implementation kept out of the main binary. Not encryption, not a security boundary.

serverlet X via python(source: "...")Shipped

A persistent Python 3.10+ process behind the same interface. Startup checks the declared handlers; budgets bound how long a caller waits.

serverlet X via typescript(source: "...")Shipped

TypeScript 7 checks the source; scriptc or Bun compiles it to an executable that keeps state between calls.

serverlet X sandbox(memory_limit, timeout)Shipped

Handlers run in a WASM guest under wasmtime, with a memory cap, a per-call timeout, and no import it was not given. A call that breaks a limit is reported and the guest is replaced, which resets its state.

Languages

Coordinate the code you already have.

OrchestrateLang is not meant to replace Rust, Python, TypeScript, or C++. It is meant to coordinate them. Direct functions stay cheap; stateful or runtime-owned code becomes a service. Measure before promising

What a boundary costs, in microseconds.

The same echo handlers behind three serverlet kinds, 2,000 measured calls each after warm-up. The pipe itself is cheap: a Rust child adds roughly 10 to 20 µs over an in-process call. Large Python arrays are dominated by per-element encoding in the SDK, which is the next optimization target. Your numbers will differ; compare cases on one machine.

Install and run

Two commands, then the smallest example.

You need Rust and Cargo. The first run builds a generated Cargo project and takes longer; later runs reuse .orch_cache/. Foreign-language examples need their own toolchain: Python 3.10+, TypeScript 7 with Bun, Zig, or Swift.

shell
git clone https://github.com/Immanuel-Fowler/OrchestrateLang
cd OrchestrateLang
cargo install --path .

orchestrate run examples/hello.orch
# the same CLI as a Cargo subcommand
cargo orch run examples/hello.orch
orchestrate run main.orchCompile and run a program
orchestrate build main.orch -o appBuild a release binary
orchestrate check main.orchParse and type-check without building
orchestrate check-foreign main.orch --deepRun each foreign language's own checker, plus mypy and generated Rust
orchestrate build --lib main.orch -o generated/scriptsGenerate an embeddable Rust crate for a host that owns the main loop
orchestrate prom add name ./moduleRegister a local module under a short name
Be honest about guarantees

What it does not promise yet.

OrchestrateLang is young. Names, docs, and diagnostics are not allowed to promise more than the implementation delivers, so the important limitations are listed here, not buried.

A sandbox contains compute, not meaningA sandboxed serverlet bounds its guest's memory, its time, and what it can reach, as well as wasmtime does. It does not make the answers the guest returns trustworthy. grant and on_crash on one are compile errors, and arrays and structs do not cross the boundary yet.
A process is not a security boundarySecret and landline serverlets give lifecycle and crash separation. "Secret" means built outside the main binary, not encrypted.
Two landline runtimesPython and TypeScript today. C# and embedded runtimes are planned.
Cross-process calls cost moreSecret serverlets and TypeScript adapters use an explicit protocol; direct calls stay in-process.
Deterministic mode is scopedIt covers host-driven lifecycle and event hooks, not spawned workers or serverlets.
Some diagnostics come from RustSet ORCH_SHOW_GENERATED=1 to see the generated source and full Cargo output.
